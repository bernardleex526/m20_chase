本文是既有 Gazebo Classic 11 的 15 工况历史验收记录；下面表格和工具链保留原始口径，不代表当前分支的全工况通过。

当前软件验证：四包构建通过，colcon 85 项零失败，pytest 77 项通过，坐标 DDS 8/8 通过（带 stamp 旋转/平移、精确时间 TF、同帧、headers、5 Hz/0.1 m 体素/6000 点、自过滤、故障归零 0.0007–0.0017 s）。step1 回环 direct_timeout 0.3090 s、binding/observation 0.5020 s、estop 0.0004 s、cloud_loss 0.5076 s 通过；缓存 clangd 四个符号引用检查成功。

最终消费者场景测试 13/13 PASS，包含 `EMERGENCY_STOP` 六分量归零；四个 C++ 测试重跑通过，colcon 85 项零失败，governor diagnostic 0。此前 12/13（`emergency_obstacle` vx=0.855）来自 0.30 m 点落入前界 0.36 m 共享自遮挡盒的旧 fixture。最终只修正消费者测试：0.45 m 低障碍位于手动前界 0.39 m 外，低带 `[-0.6,-0.5]` 与目标带不相交；六零断言加强，VFH 保持启用，生产配置与其他 fixtures 未改变。`follow_acceptance --case all` 仍退出 2，crossing/clock_pause 预留后续覆盖。完整证据与最终修正见 [step3 报告](../../../.omp/reports/step3.md)，没有硬件验证。

当前配置使用 `control_frame=base_link` 和按源 stamp 的 TF；目标/低障碍带均为控制帧显式 z 范围，低位带默认关闭。硬件 TF 与高度带未实测前保持 inactive。同帧合成 `rslidar` 仅是回环；适用边界为平地、低速、受控场景，几何跟踪无身份保证。运行/绑定/真实源点可视化契约见 [当前 README](../README.md)。

## 1. 验收判据（冻结，未为通过而放宽）

| 判据 | 含义 |
|---|---|
| **A1 不碰撞** | 物理接触传感器为 0 **且** 最小真实净空 >= 0.05 m。两条都要满足（各能捕获对方漏掉的情况：传送进机体的静态道具不产生接触力，而 2D 模型看不到机体骑上道具时的倾斜） |
| **A2 跟随精度** | 稳态 `|range - follow_dist| <= 0.15 m` 持续 >= 2 s |
| **A3 不卡死** | 判据是**进展**而非状态字符串：安全层压住机器人 且 位姿在 1 s 内既不移动(>0.05 m)也不转向(>0.20 rad) 且 未到目标位 才算卡死。原地转向对齐缺口是进展，不算 |
| **A4 时效** | 在预算内达到目标位（S10/S13/S14/S15 目标不是"到达"，见备注） |
| **A5 重捕获** | 仅 S10：目标重新出现后必须重新锁定 |

## 3.5 GIF 可视化发现的两个缺陷（判据结构上抓不到）

把每个工况渲成 GIF 后发现：**A1–A4 无法判断"锁的是不是人"**。对着错误物体保持完美间距，也是完美间距。

| 缺陷 | 实测后果 | 状态 |
|---|---|---|
| `autoSelectFront` 取视野内**最近的一个点** | 陷阱里最近的是背面墙 → 报 `TRACKING_AUTO`，对着墙保持 0.95 m，人在 4.5 m 外；某工况 86% 时间锁错 | 已修：改取"最像人的簇"（按距离换算物理宽度 <= 0.9 m，人约 0.5 m） |
| 选择器未应用自遮挡排除 | 机顶落在目标带内，机体自身以"近距离、视野内、人宽度"的簇被选中；主循环又把它判为自遮挡 → 簇为空、测量失败 → 立刻丢锁（即日志中的 `target=LOCK ... pts=0`） | 已修：选择器同样应用自遮挡框 |
| 成簇要求"相邻 bin 都有回波" | 投影 1440 bin 但雷达只发 720 条射线，**每隔一个 bin 必空**，该条件永不成立；加上机体遮挡弧，一个人被切成 47 个单 bin 碎片，**目标丢失后永远无法重捕获** | 已修：容空洞成簇（小间隙桥接） |

新增 `scripts/check_lock_accuracy.py`：把节点目标估计与真值对比，是发现第 1 条的检查。
新增 `src/rs_follow/test/test_autoselect.cpp`：5 条断言覆盖上述全部情形。

## 4. 备注与已知边界

- **S10/S13/S14/S15 的 A4**：这些工况的目标不是"到达目标位"（搜索、人群穿行、脱困、传感器中断），A4 改为"在预算内完成运行"，`needs_reach=False`。
- **S13 需要 Re-ID 才完整**：目前靠卡尔曼预测维持同一目标，不区分外观。人群中若目标被完全遮挡并由另一人顶替，会跟错人。属方案中 P4（可选）范围。
- **动态障碍只做"让行"**：碰撞规避对移动障碍用的是"预测到达时刻 + 到时它是否还在路径上"的判据，没有做轨迹预测。S12 的行人横穿是"机器人先过"的几何（若机器人直行，横穿点净空 0.72 m），若改成两者同时到达的针尖几何，本设计不保证通过——那需要预测行人轨迹。
- **`governor_t_lat = 0.20 s` 是设计假设**，不是实测值。它包含扫描周期、控制周期、传输和执行延迟。真机必须实测并放大。仿真里基座是零延迟的 `planar_move`，所以这个值偏乐观。
- **历史 `sensor_height` 口径**：这轮仿真机体落地后雷达约 0.75 m，而非名义 0.95 m；当时低位带由传感器高度推导。该事实用于解释旧结果；当前已改为控制帧中的显式 `low_height_min/max`，不得继续套用旧推导。硬件旋转/平移 TF、地面范围与高度带须实测。

## 5. 安全层单元测试

`src/rs_follow/test/test_safety.cpp` 直接用手工构造的扫描帧驱动 `FollowController`，毫秒级验证六组行为，对应仿真中真实出现过的失效：

1. 侧墙 0.60 m 不减速；0.30 m 不冻结（可慢但必须能走）
2. 正前方障碍：速度随净空递减（0.9 -> 0.589 -> 0.330 -> 0）
3. 0.90 m 门洞可通行，不触发急停
4. 近侧向障碍限速
5. 下带能看到目标带看不到的低位障碍
6. 被跟随的人不算障碍（两个高度带都排除）

`test_governor_curve.cpp` 打印调速曲线，用于按数字而非试错来选安全边距。
